# RandomWars MVP 계획

> 버전 0.1 (2026-09-28) · 기획서: [01-기획서.md](01-기획서.md)

## 1. MVP 목표

**규칙 1~8이 전부 실제로 돌아가는 가장 작은 게임.** 무기는 100종이 아니라 **12종**으로 시작하되, 카운터·연계가 실제로 느껴지도록 고른다. 친구 몇 명이 들어와 30분 동안 입장 → 파밍 → 교전 → 보급 쟁탈 → 사망 → 재입장을 막힘 없이 반복할 수 있으면 MVP 완료.

### 포함
- 랜덤상자(일반/보급), 무기 레지스트리, 확률표
- 로비 ↔ 플레이존, 랜덤 워프, 입장 보상, 처치 보상, 사망 소멸
- 전투 상태, 엔더상자 제한, 전투 로그아웃 처리
- 10분 보급
- 스킬 부품 약 10개, 무기 12종, Blockbench 모델 최소 3종 + 리소스팩 자동 적용

### 제외 (MVP 이후)
- 무기 100종 확장, 밸런스 수치 조정 도구
- DB 저장(전적, 랭킹), 킬스트릭 스코어보드
- 맵 제작 자체 (MVP는 임시 테스트 맵 사용)
- 관리자 GUI 에디터

## 2. 기술 기본값

| 항목 | 선택 | 이유 |
|---|---|---|
| 언어/빌드 | Kotlin + Gradle Kotlin DSL, JDK 21 | 사용자 환경(IntelliJ), Paper 1.21.x 요구 JDK |
| API | `io.papermc.paper:paper-api:1.21.11-R0.1-SNAPSHOT` (compileOnly) | |
| 배포 | Shadow 플러그인으로 Kotlin stdlib 포함 jar 1개 | 서버에 별도 라이브러리 설치 불필요 |
| 구성 | 단일 플러그인 `RandomWars`, 기능별 패키지 | 무기 레지스트리·사망 규칙을 모든 기능이 공유 |
| 데이터 | YAML (`weapons.yml`, `loot.yml`, `regions.yml`, `config.yml`) | 무기 추가를 코드 수정 없이 |
| 아이템 식별 | PDC (`randomwars:box_tier`, `randomwars:weapon_id`) | 이름 조작·중복 판정에 안전 |
| 테스트 서버 | 사용자 PC 폴더의 Paper 1.21.11 (별도 스레드에서 구축) | |

패키지 구조:
```
com.randomwars
├─ RandomWarsPlugin.kt
├─ box/        랜덤상자 아이템, 개봉 연출, 확률표
├─ weapon/     무기 정의·레지스트리·아이템 생성
├─ skill/      스킬 부품, 쿨다운
├─ zone/       로비/플레이존, 랜덤 워프, 입장 보상
├─ combat/     전투 상태, 처치 판정, 사망 소멸
├─ enderchest/ 엔더상자 제한
├─ supply/     보급 스케줄러, 지역
└─ pack/       리소스팩 전송
```

## 3. 단계별 계획

각 단계는 `develop`에서 기능 브랜치 → PR → `develop` 병합. 단계마다 테스트 서버에서 **완료 기준**을 직접 확인한다.

### M0. 준비
- GitHub `RandomWars` 저장소 생성 (사용자), `develop` 브랜치, 문서 이동
- Gradle Kotlin 프로젝트 뼈대, 빌드 시 jar가 테스트 서버 `plugins/`로 복사되게 설정
- 리소스팩 파이프라인 확인: Blockbench 모델 1개 → 리소스팩 → 서버 접속 시 자동 적용 → 게임에서 모델 보임
- **완료 기준**: `/rw version`이 응답하고, 테스트 모델이 들린 아이템이 게임에서 보인다.

### M1. 랜덤상자 ← 첫 번째 개발 대상
- 일반/보급 랜덤상자 아이템 (PDC 태그, 전용 모델)
- 우클릭 개봉: 1개 소모 → 1.5초 룰렛 연출 → 결과 지급. 설치 불가, 인벤토리 가득 차면 거부
- `loot.yml` 등급 확률 → 등급 안에서 무기 균등 추첨
- 무기 레지스트리 최소 버전: 스킬 없이 이름·등급·모델만 있는 더미 무기 12종
- 관리자 명령: `/rw box give <플레이어> <일반|보급> [개수]`, `/rw reload`
- **완료 기준**: 상자 1,000개 시뮬레이션(`/rw box sim`) 결과가 확률표와 ±2% 이내, 게임에서 개봉 연출과 지급이 정상.

### M2. 플레이존과 생명주기
- 로비/플레이존 월드 설정, `/입장`(또는 포탈) 
- 랜덤 워프(안전 좌표 탐색 + 후보 지점 대체), 입장 3초 무적
- 한 목숨당 1회 상자 2개 지급
- 사망 시 드롭·경험치 전부 제거, 로비 부활
- 처치 보상 1개 (최근 공격자 판정, 같은 상대 5분 내 중복 보상 없음)
- **완료 기준**: 입장 → 2개 획득 → 처치 → 1개 획득 → 사망 → 바닥에 아무것도 없음 → 재입장 → 다시 2개 획득.

### M3. 전투 상태와 엔더상자
- 플레이어 간 피해 시 15초 전투 상태, 액션바 표시
- 전투 중 엔더상자 열기 차단, `/로비` 차단 (`/로비`는 5초 제자리 대기)
- 전투 로그아웃 = 사망 처리 + 처치 보상
- **완료 기준**: 교전 직후 엔더상자가 열리지 않고 15초 뒤 열린다. 전투 중 접속 종료한 플레이어의 아이템이 소멸한다.

### M4. 보급품
- `regions.yml`에 지역명·중심 좌표·반경 등록, `/rw region add <이름>`으로 현 위치 등록
- 10분 주기 스케줄러: 지역 2곳에 보급 상자 블록 생성, 공지(채팅/타이틀/보스바), 선착순 개봉 시 보급 랜덤상자 지급
- 다음 주기에 미개봉 상자 제거, 서버 재시작 시 상태 정리
- **완료 기준**: 주기를 1분으로 줄인 테스트 설정에서 생성·공지·획득·제거가 반복된다.

### M5. 무기와 스킬 (12종)
- 스킬 프레임워크: 우클릭 트리거, 쿨다운(액션바/아이템 쿨다운 표시), 스킬 부품 인터페이스
- 스킬 부품 약 10개: 돌진, 등 뒤 이동, 연타, 기절, 둔화, 넉백, 투사체, 범위 폭발, 보호막, 표식
- 무기 12종을 YAML로 정의. 반드시 들어갈 조합:
  - 연계: 등 뒤 이동 무기 + 연타 무기
  - 카운터: 연타 ↔ 보호막, 돌진 ↔ 둔화, 원거리 ↔ 돌진
- Blockbench 모델 3종 이상(랜덤상자 1, 무기 2) + 스킬 이펙트 1종을 `ItemDisplay`로 표현
- **완료 기준**: 2인 테스트에서 연계 조합으로 순삭이 가능하고, 카운터 무기를 든 쪽이 체감상 유리하다.

### M6. 플레이테스트
- 3~5명 30분 플레이, 문제 목록 작성 → 수정
- 로그: 상자 개봉 결과, 처치, 보급 획득 (밸런스 자료)
- **완료 기준**: 치명적 버그(아이템 복제, 소멸 누락, 서버 오류) 0건.

## 4. MVP 이후 로드맵 (요약)
1. 무기 30종 → 60종 → 100종+ (스킬 부품 25~30개로 확장), 상성표 문서화
2. 전적·랭킹 DB, 킬스트릭 스코어보드
3. 정식 맵 제작과 지역 배치
4. 밸런스 조정용 관리자 명령/GUI

## 5. 첫 작업 (저장소가 생기면 바로)
1. `develop` 브랜치에 `docs/` 이동, Gradle 뼈대 커밋
2. M0 리소스팩 파이프라인 확인 (Blockbench MCP 연결 후 랜덤상자 모델 1개)
3. M1 랜덤상자 개발 시작
